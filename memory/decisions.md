# 결정 기록

## 2026-08-21 — 역할과 발행 운영기준

- **역할**: SNS 마케터 겸 개발자 비서. 사용자는 SEO와 블로그 구조를 모른다는 전제로
  설명한다. 원고 제작을 통째로 맡는다.
- **1순위 채널**: 네이버 블로그(검색 유입 + 홈판), 티스토리(구글 노출 + 애드센스 승인).
  브랜드 구축이 목적이므로 주제를 흩뜨리지 않는다.
- **하루 편성**: 네이버 3편(검색형 2 + 홈피드형 1), 티스토리 3편(롱폼/가이드/비교),
  이미지 8~10장 프롬프트, 인스타 카드뉴스 프롬프트. 상세 기준은
  `standards/발행-운영기준.md`.
- **속도를 조절하기로 함**: 첫날부터 하루 3편은 네이버 저품질·애드센스 거절 위험이
  크다. 1주차 1편 → 2주차 2편 → 3주차부터 3편을 권고했다.
- **발행 방식**: 복사·붙여넣기까지는 사용자가 한다. 티스토리 API가 종료됐고 네이버
  자동 로그인은 계정 제재 위험이 있어, 발행 직전 사람이 한 번 보는 편이 낫다.
- **전달 방식**: 매일 결과를 Artifact 링크로 낸다(주소 고정, 즐겨찾기 하나). 원본은
  드라이브에 쌓는다. 운영기준 설계서:
  https://claude.ai/code/artifact/f87ee1c0-2340-4ab1-930e-05a8f2396f7a
- **미결**: 매일 9시 실행 위치 — 클라우드(네이버 API·인스타 못 씀) vs 사용자 PC(전부 씀).

## 2026-08-21 — 발행 자동화: 티스토리는 막혔고 네이버는 조건부

- **티스토리 Open API는 2024년 2월에 완전 종료됐다.** 글쓰기·수정·첨부·댓글 전부.
  신규 발급도 기존 키도 못 쓴다. 다시 알아볼 필요 없다.
  → 티스토리 자동 발행은 브라우저 자동화 외에 방법이 없다.
- **네이버 블로그 글쓰기 API는 남아 있다.** 단 '네이버 아이디로 로그인' 연동으로
  access token을 받아야 한다. 검색 API와는 다른 계열이다.
  → **미확인: 임시저장(draft) 지원 여부.** 네이버 개발자 문서가 이 환경에서
  막혀 확인 못 했다. 사용자 PC에서 확인할 것.
- **브라우저 자동화는 마지막 수단으로 남긴다.** 네이버가 자동화 로그인에 민감해
  계정 제재 위험이 있다. 블로그 계정 손실은 되돌릴 수 없으므로 감수할 위험이 아니다.
- **당분간 '붙여넣기 완성본' 방식으로 간다.** 티스토리 HTML 모드에 그대로 붙여넣을
  수 있는 형태로 글을 뽑아준다. 발행 전 사람이 한 번 보게 되는 것도 이점이다.

새 항목을 맨 위에 추가한다. 각 항목은 무엇을 정했는지와 왜 그렇게 정했는지를 남긴다.

## 2026-08-21 — 드라이브 폴더 구조 재편

- 기준(루트) 폴더는 기존 `내 드라이브/성글벙글 원소스 멀티콘텐츠 자동화 구현/`을 그대로 쓴다.
  새 폴더를 만들지 않는다.
- 재편 이전에 있던 자료 3건(운영기준 문서, `00_발행일정표/`, `2026-08-13_국가장학금` 폴더)은
  삭제하지 않고 `_archive/`로 옮겼다. 필요하면 거기서 꺼내 쓴다.
- 폴더는 번호 접두사로 정렬한다: `00_기준문서`, `01_작업`, `02_발행일정표`, `09_메모리`.

## 2026-08-21 — 동기화 방식

- 컴퓨터 세 대(집·회사·노트북) 모두 구글 드라이브 데스크톱 앱이 설치되어 있어,
  로컬 폴더 복사 방식으로 동기화한다. API 업로드보다 빠르고 오프라인에서도 동작한다.
- 삭제는 전파하지 않는다(`rsync --update`, `--delete` 없음). 한쪽에서 실수로 지운
  파일이 다른 컴퓨터에서 사라지는 사고를 막는 편이, 지운 파일이 되살아나는
  불편보다 낫다고 판단했다.
- git이 정본이다. 드라이브는 컴퓨터 간 전달 수단이자 백업이다.
