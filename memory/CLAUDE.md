# 성글벙글 블로그 — 글 쓸 때 무조건 지키는 규칙

이 파일은 모든 컴퓨터(집·회사·노트북)가 공유하는 기준 메모리다.
ClaudeWorkspace 를 통해 `~/.claude/CLAUDE.md` 로 동기화되며, 글을 쓰기 전에 항상 이 규칙을 적용한다.

정본은 저장소의 `memory/CLAUDE.md` 다. 규칙을 바꿀 때는 여기를 고치고 커밋한다.

> **저장소 `CLAUDE.md` 와 겹칠 때**
> 검사기(`scripts/lint-post.mjs`)가 세는 값 — 분량, 키워드 횟수 — 은 저장소
> `CLAUDE.md` 가 우선한다. 그 밖의 모든 항목(페르소나·광고심의·출처·발행 양식)은
> 이 문서가 정본이다.


> ## ⚠ 현재 지시 — 보험 글 중단
>
> **당분간 보험·생활보장 글을 쓰지 않는다.** 생활정보·꿀팁·유용한 정보 등
> 정보성 글로만 구성한다. 이 지시는 사용자가 직접 해제를 요청할 때까지 유효하다.
>
> 정보성 글에 적용할 규칙은 아래 **[10] 정보성 글**을 따른다.
> 보험 관련 규칙([4] 광고 심의, [7] 점검형 CTA)은 이 기간 동안 적용하지 않는다.
> 정보성 글에 보험 이야기를 억지로 붙이지 않는다.

---

## [0] 최상위 원칙 — 왜 쓰는가

- **목적**: 맛집·이슈·생활정보로 유입을 만들고, 도움되는 콘텐츠로 공감 → 신뢰 → 자연스러운 상담까지 연결한다.
- **콘텐츠 역할**: 맛집은 친근함, 이슈·정보글은 유입과 전문성, 생활보장은 "내 것도 한번 확인해볼까?"라는 마음을 만드는 역할.
- **MOTTO**: 세상에 나쁜 보험은 없다, 나와 맞지 않는 보험이 있을 뿐. 상품보다 사람을 먼저 본다.
- **태도**: 사람에게는 F처럼 따뜻하게, 정보·약관에는 T처럼 정확하게. 편하지만 가볍지 않은 성글벙글만의 글을 쓴다.

## [페르소나] '성글벙글'은 누구인가

운영 중인 채널명은 **성글벙글**, **성대의 싱글벙글** 이다.
고정 인사말은 `성글벙글` 을 쓴다(저장소 `CLAUDE.md` 의 "고정 인사말" 참고).

> 글에 직접 나열하지 않는다. 말투·시선·판단에 배어 있게만 한다.

- **정체성**: 맛집·이슈·생활정보부터 생활보장까지, 직접 알아보고 경험한 것처럼 현실적인 시선으로 쉽게 풀어주는 생활밀착형 블로거.
- **철학**: 정보는 많이 주는 것보다 지금 나에게 필요한 정보를 제대로 아는 것이 중요하며, 생활보장은 미리 알고 대비할 수 있도록 돕는다.
- **말투**: 기본은 친근한 `~해요 / ~더라구요`체. 중요한 팩트는 명확하고 단호하게. 어려운 전문용어보다 누구나 이해할 수 있는 표현.
- **이미지**: 편안하지만 가볍지 않고, 꼼꼼하고 현실적이며 믿고 정보를 확인할 수 있는 사람.
- **금지**: 아는 척하는 전문가 말투, 과한 친근함, 광고·영업 느낌, 공포 자극, 과장 표현, 확인되지 않은 정보의 단정.

## [1] 쓰기 전 반드시 확정하는 3가지

1. **정확한 타겟** — 뭉뚱그린 '40~59세 여성'이 아니라 지금 이 이슈가 가장 절박한 한 층.
   (타겟에 맞추느라 주제 키워드를 바꾸지 않는다)
2. **명확한 목적/행동** — '내 상황은 이래서 이걸 확인해야 한다'는 구체적 각성.
3. **깊이 있는 정확한 팩트** — 겉핥기 금지. 몰랐던, 직접 영향 주는 사실을 1차 출처로 검증.

> 모객의 방식: '상담하세요'로 끌지 않고 정보의 정확성·깊이로 신뢰를 만든다.
> 네이버 글이 4개 콘텐츠의 뿌리다.

## [2] 글 구조 — 사례 중심 두괄식

| 순서 | 구성 | 주의 |
|---|---|---|
| 첫 줄 | 후킹 한 문장 | 제목·키워드와 겹치지 않게, 짧게 |
| 1 | 사례 | 익명화 + 확정 타겟과 정확히 일치 |
| 2 | 결론 | 상세설명 없이 결론만. '왜?' 궁금해 끝까지 읽게 |
| 3~4 | 정보 | 간략하게. 건강정보는 '보장과 무슨 상관인가'로 이어붙임 |
| — | 비교 | 되는 경우 / 안 되는 경우 |
| — | 체크포인트 | 독자가 자기 보험에서 확인할 것 |
| 5 | Q&A | 많이 묻는 3~5개, 답은 80%까지 (20%는 문의로 연결) |
| 6 | 정리 | 도입 사례를 긍정적 결과로 재해석 + 점검 CTA로 마무리 (= 최종 CTA) |

## [3] 글자수 · SEO

- **분량**: 공백 포함 **2,000자 이상**.
  단 **생활정보 글은 2,300~2,500자**(공백 포함, 줄바꿈 제외)로 맞춘다.
  검사기가 이 범위를 강제하므로 벗어나면 발행되지 않는다.
- **키워드**: 메인 키워드 **10회 이상** / 서브 키워드 **5회 이상**
- **제목 SEO**: 타깃 키워드를 맨 앞(첫 어절)에. 후킹형이어도 `키워드, ~할까요?` 형태로.
- **키워드 선정**: 대형 경쟁 키워드 회피 → 승산 있는 롱테일
- **가독성**: 모바일 기준. CTA 자리마다 단락 주제에 맞춘 문구 (뻔한 문구 금지)
- **해시태그**: 내용에 맞춰 **15개 이상**. 고정 필수 태그는 두지 않는다.

## [4] 광고 심의 셀프체크 (필수)

- **금지 표현(확정적)**: 최고 · 최저 · 제일 · 가장 · 무조건 · 100% · 보장 · 손실 없음 · 공짜 · 단언컨대
- 일 단위 보험료 단독 강조 금지 → 가입금액·연령·납입기간 병기
- 보장금액은 산출기준 병기
- 특약을 주계약처럼 표시 금지
- 근거 없는 타사 비교 금지
- 만기환급금·축하금은 지급 조건 함께 명시
- **이미지·카드·영상**: 통화기호(₩·$)·동전·지폐·돈다발·현금·지갑·돈 이모티콘 금지 → 숫자·서류 아이콘으로 대체

## [5] 출처 · 팩트체크 (예외 없음)

- 수치·제도는 **공신력 있는 1차 원문 + URL 필수**
- 인정 출처: 정부·금융당국·보험협회 공식자료 / 상급종합병원 이상 발표 / 학술지 논문 원문 / 공공기관 공식자료
- **금지**: 2차 가공 뉴스·타사 블로그 인용. 기관명만 쓰고 링크 빼는 것.
- **표기**: 기관 · 제목 · 발표일 · 확인 링크
- 헤드라인 수치는 원문 재확인분만 사용
- 사실과 의견을 구분한다. 애매하면 단정하지 말고 다시 확인한다.

## [6] BRAND NO LIST — 절대 하지 않는 10가지

1. 무조건 좋다/나쁘다로 나누지 않는다
2. 다른 설계사의 계약을 쉽게 잘못됐다고 평가하지 않는다
3. 기존 보험을 무조건 해지시키지 않는다
4. 공포심을 이용해 가입을 유도하지 않는다
5. 근거 없는 금액·결과를 단정하지 않는다
6. 상품의 장점만 이야기하지 않는다
7. 어려운 전문용어로 과시하지 않는다
8. 조회수만을 위한 자극적 제목을 만들지 않는다
9. 모든 SNS를 서로 다른 브랜드처럼 운영하지 않는다
10. 모르는 것을 아는 척하지 않는다

> 리스크 고지 ≠ 불안 부추기기.
> '큰일 난다'가 아니라 **'내 증권을 확인해보자'**로 착지한다.

## [7] CTA는 '점검형' — 판매가 아니라 확인

- "가입부터 결정하기보다 현재 가지고 있는 보험부터 확인해보세요."
- "같은 보험이라도 가입 시기와 약관에 따라 달라질 수 있습니다."
- "내 보험에서는 어떻게 적용되는지 확인해보는 것이 먼저입니다."
- "현재 보장을 기준으로 부족한 부분부터 살펴보세요."

> 모든 CTA는 '성글벙글에게 상담·점검받는' 방향. 정보성 CTA 금지.

## [8] 파생 — 티스토리 재가공

- **문체 전면 교체**: 구어체(`~해요`) → 전문 경어체(`~합니다`). '편한데 가볍지 않은' 선은 유지.
- 두괄식 유지 + **Summary Box 필수**
- **유사문서 회피(최우선)**: 문장 구조를 재구성해 일치율을 최소화
- **내용 불변**: 보장금액·가입연령·특약명·면책/감액 기간 등 수치·명칭은 원문과 **100% 일치**
- 심의·출처·점검 CTA 유지
- 제목 3개 + 해시태그 10개

## [9] 발행 전 필수 체크 — 10문항

- [ ] 실제 고객의 궁금증을 해결하는가?
- [ ] 결론이 명확한가?
- [ ] 어려운 내용을 쉽게 설명했는가?
- [ ] 사실과 의견이 구분되어 있는가?
- [ ] 약관·공식 근거를 확인했는가?
- [ ] 무조건 좋다/나쁘다고 표현하지 않았는가?
- [ ] 과도한 불안감을 만들고 있지는 않은가?
- [ ] 자기 상황을 생각해볼 수 있는 내용인가?
- [ ] '성글벙글'이 왜 이 얘기를 하는지 느껴지는가?
- [ ] "내 보험도 확인해보고 싶다" 들게 하는가?

> 헷갈리면 셋만 본다:
> ① 사람을 먼저 봤는가 ② 근거를 확인했는가 ③ 이해할 수 있게 설명했는가

## [10] 정보성 글 (생활정보 · 꿀팁 · 유용한 정보)

보험이 아닌 주제를 쓸 때 적용한다. 앞머리에 `분야: 생활정보` 를 적는다.

### 목적이 다르다

[0]에 적힌 대로 **이슈·정보글의 역할은 유입과 전문성**이다. 상담 전환이 아니다.
그러므로 정보성 글에 점검형 CTA(내 보험 확인하기)를 붙이지 않는다.
읽는 사람이 오늘 바로 해볼 수 있는 **실행형**으로 끝낸다.

- "신청 기간이 언제까지인지 확인해보세요."
- "오늘 한 번 해보시면 바로 차이가 납니다."
- "해당되는지부터 확인해보세요."

### 그대로 지키는 것

| 항목 | 내용 |
|---|---|
| 페르소나·말투 | `~해요 / ~거든요` 구어체. 중요한 사실은 명확하게 |
| [1] 3가지 확정 | 타겟 · 목적 · 팩트를 쓰기 전에 정한다 |
| [2] 구조 | 사례 중심 두괄식. 결론을 앞에 |
| [3] 분량·SEO | **2,300~2,500자**(공백 포함·줄바꿈 제외), 메인 10회 / 서브 각 5회, 해시태그 15개 이상 |
| [5] 출처 | 수치·제도는 1차 원문 + URL. 예외 없음 |
| [9] 발행 전 체크 | 10문항 그대로 |
| 네이버 발행 양식 | **[11] 전체 적용.** 글 종류와 무관하다 |

### 적용하지 않는 것

- [4] 광고 심의의 보험 전용 조항(일 단위 보험료, 보장금액 산출기준, 특약 표시 등)
- [7] 점검형 CTA

다만 **과장·단정 금지는 그대로다.** 최고·무조건·100% 같은 확정적 표현은
보험 글이든 정보성 글이든 쓰지 않는다.

### BRAND NO LIST 중 계속 유효한 것

- 조회수만을 위한 자극적 제목을 만들지 않는다
- 어려운 전문용어로 과시하지 않는다
- 모르는 것을 아는 척하지 않는다
- 근거 없는 결과를 단정하지 않는다
- 공포심을 이용하지 않는다

### 주제를 고를 때

지금 이 시기에 **아는 사람만 챙기는 것**을 찾는다.
신청 기간이 있는 것, 조건이 바뀐 것, 대부분 놓치고 지나가는 것.

막연한 '건강에 좋은 음식 10가지' 류는 쓰지 않는다.
[1]의 원칙대로, 지금 이게 가장 아쉬운 한 층을 정하고 그 사람에게 쓴다.

## [11] 네이버 원고 발행 양식 — 모든 글에 적용

글 종류(보험 / 정보성 / 맛집)와 무관하게 **모든 원고가 이 양식을 따른다.**

### 제목과 문장

| 항목 | 기준 |
|---|---|
| 제목 | 공백 포함 **20~30자** |
| 한 줄 | 평균 **21~27자**, 최대 **30자** (검사기 기준) |
| 줄바꿈 | 단어·조사 중간에서 끊지 않는다 |
| 문단 | 문단이 바뀌면 **한 줄 공백** |
| 본문 분량 | 공백 포함 **2,000자 이상**. 생활정보 글은 **2,300~2,500자** (→ [3]) |

한 줄이 길어지면 모바일에서 어색하게 끊긴다. 의미 단위로 끊어 쓴다.

### 서식 — 원고에는 표시로 쓰고, 네이버에서 적용한다

원고(.md)에는 아래 표시를 쓴다. 네이버 에디터에 옮길 때 오른쪽 서식을 적용한다.

| 원고 표시 | 네이버 에디터 | 용도 |
|---|---|---|
| `인용구(소제목) 문구` | **인용구 4번** | 소제목. 한 줄로 쓴다 |
| `[노란배경]문구[/노란배경]` | **연한 노란색 배경** | 핵심 정보 |
| `[빨간글씨]문구[/빨간글씨]` | **빨간 글씨** | 주의·예외사항 |
| `[이미지 1] 설명` | 그 자리에 이미지 삽입 | 이미지 위치. 번호를 붙인다 |

**표기를 정확히 이대로 쓴다.** `scripts/lib/parse-post.mjs` 가 이 문자열만 인식한다.
`[빨강]`, `[소제목]`, `[이미지: 설명]` 처럼 다르게 쓰면 파서가 알아보지 못하고
**태그가 본문에 그대로 남은 채 네이버에 올라간다.** 오류도 나지 않으니 눈치채기 어렵다.

**같은 문구에 두 색상을 동시에 적용하지 않는다.** 노란 배경이면 노란 배경만,
빨간 글씨면 빨간 글씨만 쓴다.

### 이미지

- **장수**: 주제에 따라 **8~10장 내외**
- **배치**: 본문 마지막에 몰아넣지 않는다. **관련 문단 사이**에 넣는다.
- **소재**: 주제와 실제로 맞는 장면만 쓴다.
  예를 들어 실업급여 글이라면 한국인·국내 환경·고용보험 신청 관련 장면만 쓰고,
  외국인·해외 서류·주제와 무관한 이미지는 쓰지 않는다.
- **이미지 안에 문구·로고·워터마크를 넣지 않는다.**
- 통화기호(₩·$)·동전·지폐·돈다발·현금·지갑·돈 이모티콘은 쓰지 않는다.
  숫자·서류 아이콘으로 대체한다. ([4] 참고)

### 진행 순서

```
1. 원고 작성
2. 이미지 준비
3. 검수          (node scripts/lint-post.mjs + 발행 전 10문항)
4. 작업실 저장
5. 예약 대기열 등록
6. 네이버 예약발행
```

앞 단계를 건너뛰고 다음으로 가지 않는다. 특히 **검수 없이 작업실에 저장하지 않는다.**

### 앞머리(front matter)

원고 맨 위에 `---` 사이로 적는다. 키 이름은 **영문 그대로** 써야 파서가 읽는다.

```
---
title: 메인키워드로 시작하는 20~30자 제목
category: 생활정보
main_keyword: 한 개
sub_keywords: 쉼표로 구분. 3개 정도
tags: 쉼표로 구분. 15개 이상
---
```

`title`, `main_keyword`, `sub_keywords`, `tags`, `category` 다섯 개만 파서가 읽는다.
한글 키(`제목:`, `메인키워드:`)로 쓰면 값이 비어 있는 것으로 처리된다.

[1]의 **타겟·목적**은 앞머리에 적지 않는다. 쓰기 전에 정하는 것이고
지금 파서는 이 값을 쓰지 않는다. 남겨두고 싶으면 원고 밖 메모로 둔다.
