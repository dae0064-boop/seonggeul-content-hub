# 생활정보 원고 작성

검사기(`scripts/lint-post.mjs`)가 세는 값은 **이 문서가 최종**이다.
말투·금지표현 같은 브랜드 전반 규칙은 `memory/CLAUDE.md` 가 정본이다.

작성 후 반드시 검사기를 돌린다. 통과하지 못하면 발행하지 않는다.

```bash
node scripts/build-post.mjs content/posts/<원고>.md   # .md → .json
node scripts/lint-post.mjs  content/posts/<원고>.md   # 게이트
# 또는 한 번에
npm run check content/posts/<원고>.md
```

## 쓰기 전 확정할 3가지

타겟 · 목적 · 팩트를 쓰기 전에 정한다. 정본은 `memory/CLAUDE.md` 의 같은 항목이다.

타겟·목적은 front matter 에 적지 않는다. 쓰기 전에 정하는 것이고 파서가 쓰지 않는다.
남겨두고 싶으면 원고 밖 메모로 둔다.

## 주제를 어떻게 잡는가

주제는 **시기성 + 꾸준한 유입**이 겹치는 지점으로 잡는다. 특정 시즌에 검색이 몰리되,
매년 반복되어 재사용 가능한 것.

```
[계절 전환점] × [생활 축] × [동작 단위]
```

**큰 키워드 하나를 노리지 않는다.** "환절기" 같은 덩어리는 작은 질문 40개로 둘러싼다.
환절기 → 뷰티 10개 + 건강 15개 + 살림·난방 15개 로 쪼개는 식이다.

**동작 단위까지 내려간다.** "에어컨 정리"가 아니라 "에어컨 청소하고 커버 씌우는 법",
"선풍기 정리"가 아니라 "선풍기 날개 분리하는 순서". 사람이 검색창에 치는 단위다.

지금 이 시기에 **아는 사람만 챙기는 것**을 찾는다. 신청 기간이 있는 것, 조건이 바뀐 것,
대부분 놓치고 지나가는 것. 막연한 '건강에 좋은 음식 10가지' 류는 쓰지 않는다.

제목은 네 가지 형태 중 하나로 잡는다:

| 형태 | 예 |
|---|---|
| 순서 | 냉장고 비우는 순서 / 스킨케어 순서 바꾸는 법 |
| 방법 | 정전기 잡는 법 / 외풍 막는 법 |
| 시기 | 단풍 절정 시기 / 로션에서 크림 넘어가는 시기 |
| 비교·계산 | 가습기 종류별 장단점 / 온풍기 전기세 |

### 무엇을 버리는가

**공식 기관이 상단을 독점하는 키워드는 검색량이 아무리 커도 버린다.**
개인 블로그가 이길 수 없다. 787,700의 0%보다 3,000의 30%가 크다.

| 버림 | 검색량 | 독점 |
|---|---|---|
| 근로장려금 | 787,700 | 국세청 |
| 추석기차표예매 | 165,600 | 코레일 |
| 국가장학금 | 136,200 | 한국장학재단 |
| 전입신고 | 73,500 | 정부24 |

노리는 자리는 **답하는 공식 기관이 없는 생활 노하우**다. 정부24는
"선풍기 날개 분리 순서"를 안내하지 않는다.

### 검색광고 API 의 `경쟁정도` 를 그대로 믿지 말 것

그 값은 **광고주 입찰 경쟁도**이지 블로그 노출 경쟁이 아니다.
근로장려금이 "낮음"으로, 추석선물추천이 "높음"으로 나온다 — 블로그 SEO 기준과
오히려 반대다. 이 열로 고르면 정확히 잘못 고른다.
경쟁 판단은 "공식 기관이 답하는 주제인가"로 한다.

### 연간 골격 (매년 반복)

| 시기 | 전환점 | 축 |
|---|---|---|
| 9월 | 여름→가을 | 냉방기 정리 · 이불 교체 · 환절기 진입 |
| 10월 | 나들이 · 난방 준비 | 단풍 · 외풍 · 보일러 |
| 11월 | 겨울 진입 | 김장 · 난방비 · 건조 |
| 12~1월 | 한파 · 명절 | 결로 · 설 준비 · 실내습도 |
| 2~3월 | 겨울→봄 | 봄 대청소 · 미세먼지 · 환절기(2차) |
| 4~5월 | 봄 절정 | 나들이 · 자외선 시작 · 가정의달 |
| 6~7월 | 장마 | 에어컨 꺼내기 · 곰팡이 · 습기 |
| 8월 | 폭염 | 전기요금 · 휴가 · 열대야 |

**환절기는 1년에 두 번(9월·3월) 온다.** 9월 원고가 3월에 다시 돈다.

### 클러스터 운영

1. 한 클러스터 = 10~15개를 2주에 걸쳐 발행
2. 서로 내부 링크로 연결한다
3. **검색은 이벤트 2주 전부터 붙는다.** 그때 발행을 시작한다
4. 이듬해 같은 시기에 날짜·수치만 갱신해 재발행한다

하루 5개는 이렇게 배분한다:

```
정보성 2   → 순서 / 방법      (기둥글, 매년 재사용)
검색유입 2 → 시기 / 비교·계산  (시즌 타이밍)
홈판 1     → 경험 · 후기       (공감)
```

## 분량과 키워드 (검사기가 센다)

- 본문 **2,300~2,500자**. 공백 포함, 줄바꿈 제외로 센다(네이버 기준).
  공백 제외로 세면 30% 넘게 어긋난다.
- 제목 **20~30자**, 공백 포함.
- front matter 에 **`main_keyword`** 와 **`sub_keywords`** 를 반드시 적는다.
- **메인 키워드 10회 이상, 서브 키워드는 각각 5회 이상** 자연스럽게 녹인다.
  억지로 끼워 넣어 문장이 어색해지면 안 된다. 소제목과 Q&A, 정리에
  나눠 배치하면 자연스럽게 채워진다.
  서브 키워드는 5회를 자연스럽게 채울 수 있는 것으로 **3개 정도만** 고른다.
- **제목은 메인 키워드로 시작한다.** 타깃 키워드가 첫 어절이어야 한다.
  후킹형으로 갈 때도 `키워드, ~할까요?` 처럼 키워드를 앞에 둔다.
- **해시태그 15개 이상**, 내용에 맞춰 단다. 고정 필수 태그는 두지 않는다.
- 대형 경쟁 키워드는 피하고 승산 있는 롱테일로 간다.

## 모바일 가독 포맷

블로그 독자는 대부분 모바일이다. 줄바꿈이 곧 가독성이다.

기준은 실제 발행글(119 안심콜) 실측치다 — 3,066자 / 평균 줄 19.8자 / 최장 29자 / 덩어리당 3.4줄.

- **한 줄 평균 24자 안팎, 최대 30자.** 검사기는 평균 21~27자를 권장 구간으로 본다.
  글자수로 자르지 말고 **의미 단위로 끊는다.**
  모바일에서 한 줄에 들어갈 길이면 굳이 끊지 않는다.
  글자수를 채우려고 끊으면 문장이 토막 나 읽기 더 나빠진다.
  끊는 자리는 쉼표, 접속, 호흡이 끊기는 곳이다. 단어·조사 중간에서 끊지 않는다.
- **3~4줄이 한 덩어리**, 덩어리 사이에 빈 줄. 1~2줄로 잘게 쪼개지 않는다.

강조는 아껴 쓴다. 다 칠하면 강조가 강조로 보이지 않는다.
빨간글씨는 글의 **처음(안 하면 생기는 문제)과 끝(결론)** 에 걸어
스크롤을 빠르게 내리는 독자가 그 둘만 봐도 요지를 잡게 한다.

## 서식 표기 — 원고에는 표시로, 네이버에서 적용

| 원고 표시 | 네이버 에디터 | 용도 |
|---|---|---|
| `인용구(소제목) 문구` | **인용구 4번** | 소제목. 한 줄로 쓴다 |
| `[노란배경]문구[/노란배경]` | **연한 노란색 배경** | 핵심 정보 |
| `[빨간글씨]문구[/빨간글씨]` | **빨간 글씨** | 주의·예외사항 |
| `[이미지 1] 설명` | 그 자리에 이미지 삽입 | 이미지 위치. 번호를 붙인다 |

**표기를 정확히 이대로 쓴다.** `scripts/lib/parse-post.mjs` 가 이 문자열만 인식한다.
`[빨강]`, `[소제목]`, `[이미지: 설명]` 처럼 다르게 쓰면 파서가 알아보지 못하고
**태그가 본문에 그대로 남은 채 네이버에 올라간다.** 오류도 나지 않으니 눈치채기 어렵다.

강조 태그는 여러 줄에 걸쳐도 된다. 다만 **같은 문구에 두 색상을 동시에 적용하지 않는다.**
노란 배경이면 노란 배경만, 빨간 글씨면 빨간 글씨만 쓴다.

## 이미지

- **장수**: 주제에 따라 **8~10장 내외**
- **배치**: 본문 마지막에 몰아넣지 않는다. **관련 문단 사이**에 넣는다.
- **소재**: 주제와 실제로 맞는 장면만 쓴다. 실업급여 글이라면 한국인·국내 환경·
  고용보험 신청 관련 장면만 쓰고, 외국인·해외 서류·무관한 이미지는 쓰지 않는다.
- **이미지 안에 문구·로고·워터마크를 넣지 않는다.**
- 통화기호(₩·$)·동전·지폐·돈다발·현금·지갑·돈 이모티콘은 쓰지 않는다.
  숫자·서류 아이콘으로 대체한다.

## 글 구조 (사례 중심 두괄식)

```
고정 인사     안녕하세요 / 매일매일 좋은 날을 나누는 성글벙글입니다😊
도입          내 이야기로 연다. 툭 던지는 후킹 한 줄이 아니라
              "저도 늘 ~라고 생각했어요" 처럼 독자와 같은 자리에서 시작한다
사례          익명화. 타겟과 정확히 일치하는 한 사람
결론         상세설명 없이 결론만. "왜?"가 궁금해 끝까지 읽게
정보         간략하게. 단계나 방법
비교         되는 경우 / 안 되는 경우
체크포인트   독자가 자기 상황에서 확인할 것
Q&A          많이 묻는 3~5개
정리         도입 사례를 긍정적 결과로 재해석하며 닫는다
출처         기관·자료명·기준일
고정 인사     좋아요·공감과 이웃추가 부탁드려요💙 / 이상 성글벙글의 OO 포스팅이었습니다😎
```

**소제목에 번호를 붙이지 않는다.** "1단계 · 송풍으로 말리기" 가 아니라
"부모님 메모가 부족했던 이유", "누가 등록하면 좋을까요" 처럼
서술형이나 질문형으로 쓴다. 검사기가 번호를 잡는다.

**과신을 경계하는 문장을 곳곳에 둔다.** "완전히 대신하는 것은 아니라",
"정보가 많다고 좋은 것은 아니에요" 처럼 단정을 덜어내는 문장이
글 전체의 신뢰를 만든다.

정보성 글은 상담 전환이 목적이 아니다. 읽는 사람이 오늘 바로 해볼 수 있는
**실행형**으로 끝낸다 — "신청 기간이 언제까지인지 확인해보세요",
"오늘 한 번 해보시면 바로 차이가 납니다", "해당되는지부터 확인해보세요".

## 고정 인사말 (반드시 이대로)

모든 글은 이 두 줄로 연다.

```
안녕하세요
매일매일 좋은 날을 나누는 성글벙글입니다😊
```

그리고 이 두 줄로 닫는다. `OO` 자리에만 글 성격을 넣는다.

```
좋아요·공감과 이웃추가 부탁드려요💙
이상 성글벙글의 OO 포스팅이었습니다😎
```

닫는 인사 **바로 앞에는 출처와 기준일**을 적는다.

```
이 글은 (기관)의 (자료명)을
(연월일) 기준으로 정리했습니다.
```

## 말투

**기본은 친근한 `~해요` / `~더라구요` 체.** 중요한 팩트만 단호하게 끊는다.
편하지만 가볍지 않은 선을 지킨다. 사람에게는 따뜻하게, 정보에는 정확하게.

어려운 전문용어 대신 누구나 아는 표현을 쓴다.
직접 알아보고 경험한 사람의 시선으로 쓴다. 가르치는 말투가 아니다.

**쓰지 않는 말투:** 아는 척하는 전문가 말투, 과한 친근함, 광고·영업 느낌,
공포 자극, 확인되지 않은 정보의 단정.

### 문체 세부

- 과장된 표현("무조건", "100%", "반드시")을 쓰지 않는다. 검사기가 잡는다.
- 근거 없는 수치를 지어내지 않는다. 확인하지 못한 건 쓰지 않는다.
  그럴듯해 보이려고 숫자를 넣는 것이 가장 흔한 유혹이다.

건강·금융·법률 등 민감 주제는 **진단·처방·단정이 아닌 생활관리 수준**으로 쓰고,
글 끝에 전문가 상담 안내를 넣는다.

## 절대 하지 않는 것

- 무조건 좋다 / 나쁘다로 나누지 않는다
- 공포심으로 행동을 유도하지 않는다
- 근거 없는 수치나 결과를 단정하지 않는다
- 장점만 이야기하지 않는다
- 전문용어로 과시하지 않는다
- 조회수만 노린 자극적 제목을 쓰지 않는다
- 모르는 것을 아는 척하지 않는다

## 출처

수치와 제도는 **1차 원문 + 링크**로 확인한다.
정부·공공기관 공식자료, 상급종합병원 이상 발표, 학술지 원문.
**2차 가공 뉴스나 타 블로그 인용은 쓰지 않는다.**
사실과 의견을 구분하고, 애매하면 단정하지 말고 다시 확인한다.

## front matter 규격

원고 맨 위에 `---` 사이로 적는다. 키 이름은 **영문 그대로** 써야 파서가 읽는다.

```
---
title: 메인키워드로 시작하는 20~30자 제목
category: 생활정보
main_keyword: 한 개
sub_keywords: 쉼표로 구분. 3개 정도
tags: 쉼표로 구분. 15개 이상
---
```

`title`, `main_keyword`, `sub_keywords`, `tags`, `category` 다섯 개만 파서가 읽는다.
한글 키(`제목:`, `메인키워드:`)로 쓰면 값이 비어 있는 것으로 처리된다.

## 발행 전 점검

- 실제 궁금증을 해결하는가
- 결론이 명확한가
- 어려운 내용을 쉽게 설명했는가
- 사실과 의견이 구분되는가
- 공식 근거를 확인했는가
- 무조건 좋다/나쁘다로 말하지 않았는가
- 과도한 불안을 만들지 않는가
- 자기 상황을 떠올리게 하는가

## 진행 순서

```
1. 원고 작성
2. 이미지 준비
3. 검수          (npm run check + 위 발행 전 점검)
4. 작업실 저장
5. 예약 대기열 등록
6. 네이버 예약발행
```

앞 단계를 건너뛰고 다음으로 가지 않는다. 특히 **검수 없이 작업실에 저장하지 않는다.**
