5. 사용자가 나중에 고쳐 달라고 하면 그 날 07:00 전이면 고쳐서 다시 합친다.

## (지난 규칙, 2026-11-04~11-12) 확인받고 넣기 — 쓰지 않음
1. `git fetch origin main` 후 main 기준으로 새 `claude/*` 브랜치를 만든다. 오늘 날짜는 한국 시각(`TZ=Asia/Seoul date +%F`), 내일 = 그다음 날.
2. `content/threads/daily/<내일>.md` 가 main 에 **이미 있으면** 사용자에게 "내일 글은 이미 확인받은 것"이라고 4편을 짧게 보여 주고 끝낸다.
3. 없으면 `content/threads/daily.md` 규칙(✍ 견본 말투 · 😂 웃기면서 공감 · 갑분싸 금지 · 🔀 주제 돌려 쓰기 · 🤖 AI 티 빼기)과 지난 묶음 3~4개를 읽고 4편을 쓴다.
   시각 07:00 · 08:30 · 12:30 · 19:30 (2026-11-05 사용자 "6편으로 줄이고" — 11/6~ 일상 4편), 글마다 `주제:` 줄. 요일·계절에 맞춘다(토·일은 주말 분위기, 08:30 은 출근하는 분과 쉬는 분 모두).
   지어낸 사건(누가 한 말·통화·먹은 메뉴·기록)은 쓰지 않는다. `node scripts/threads/daily-set.mjs <파일>` 통과.
4. 브랜치에 커밋·푸시까지만 하고 **main 에 합치지 않는다.** 사용자에게 4편을 시각·주제와 함께 그대로 보여 주고
   "마음에 드시면 '좋아', 바꿀 곳은 짚어 주세요"라고 묻는다 (한국어, 짧게).
5. 사용자가 고쳐 달라면 고치고 검사기를 다시 돌려 다시 보여 준다. **"좋아·진행해"를 받으면** PR → main 에 합친다
   (PR 을 만든 결과의 번호로 합친다 — 번호를 짐작하지 않는다). 합친 뒤 "내일 07:00 부터 올라갑니다"라고만 알린다.
6. 사용자가 그날 밤 답하지 않으면 그대로 둔다(합치지 않는다). 다음 날 07:00 전에 답하면 그때 합쳐도 된다.
