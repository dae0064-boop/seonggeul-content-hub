# 스레드 일상 글 — 전날 저녁 미리 확인받기 (매일 19:47, 2026-11-04 사용자)

> 사용자: "전날마다 다음날 꺼 미리 확인받아". 그래서 **내일 일상 글 6편은 사용자가 이 대화에서 "좋아"라고 한 뒤에만 main 에 들어간다.**
> 확인을 못 받으면 내일 일상 글은 올라가지 않는다(PC 는 그날 묶음 파일이 없으면 쉰다). 밤 원고 작업(`naver-daily.md`)은 일상 묶음을 쓰지 않는다.

1. `git fetch origin main` 후 main 기준으로 새 `claude/*` 브랜치를 만든다. 오늘 날짜는 한국 시각(`TZ=Asia/Seoul date +%F`), 내일 = 그다음 날.
2. `content/threads/daily/<내일>.md` 가 main 에 **이미 있으면** 사용자에게 "내일 글은 이미 확인받은 것"이라고 6편을 짧게 보여 주고 끝낸다.
3. 없으면 `content/threads/daily.md` 규칙(✍ 견본 말투 · 😂 웃기면서 공감 · 갑분싸 금지 · 🔀 주제 돌려 쓰기 · 🤖 AI 티 빼기)과 지난 묶음 3~4개를 읽고 6편을 쓴다.
   시각 07:00 · 08:30 · 12:30 · 18:30 · 19:30 · 23:00, 글마다 `주제:` 줄. 요일·계절에 맞춘다(토·일은 주말 분위기, 08:30 은 출근하는 분과 쉬는 분 모두).
   지어낸 사건(누가 한 말·통화·먹은 메뉴·기록)은 쓰지 않는다. `node scripts/threads/daily-set.mjs <파일>` 통과.
4. 브랜치에 커밋·푸시까지만 하고 **main 에 합치지 않는다.** 사용자에게 6편을 시각·주제와 함께 그대로 보여 주고
   "마음에 드시면 '좋아', 바꿀 곳은 짚어 주세요"라고 묻는다 (한국어, 짧게).
5. 사용자가 고쳐 달라면 고치고 검사기를 다시 돌려 다시 보여 준다. **"좋아·진행해"를 받으면** PR → main 에 합친다
   (PR 을 만든 결과의 번호로 합친다 — 번호를 짐작하지 않는다). 합친 뒤 "내일 07:00 부터 올라갑니다"라고만 알린다.
6. 사용자가 그날 밤 답하지 않으면 그대로 둔다(합치지 않는다). 다음 날 07:00 전에 답하면 그때 합쳐도 된다.
