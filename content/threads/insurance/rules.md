# 스레드 보험 심의글 규칙 (정본)

2026-10-02 사용자 요청으로 시작했다. 같은 날 블로그(네이버)도 하루 1편 보험 정보글을 다시 쓰기로 했다
(`memory/CLAUDE.md` 맨 위 — 블로그는 비상업 정보글만). 이 문서는 **스레드 보험 심의글** 기준이다.

스레드 말투·길이·금지 표현은 `content/threads/voice.md` 를 따르고,
광고 심의·출처·BRAND NO LIST 는 `memory/CLAUDE.md` [4] [5] [6] 을 따른다.
이 문서는 그 위에 **보험 글에만 붙는 것**을 적는다.

## 한 번에 10편, 서로 겹치지 않게

보험 심의글은 **항상 10편을 한 묶음**으로 쓴다 (2026-10-02 사용자 지시. 그 전 세 묶음 2026-10-02~04 는 5편씩).
한 파일 = 한 묶음 (`content/threads/insurance/sets/<날짜>.md`, 날짜는 쓴 날 — 파일 순서를 정하는 용도).

겹치지 않게 하는 장치는 세 겹이다. 검사기가 모두 센다.

1. **역할 5칸** — 10편이 아래 다섯 역할을 **두 번씩** 맡는다. 세 번 나오면 막힌다.
2. **보험 종류** — 10편의 보험 종류가 모두 다르다 (12종 중 10종).
3. **지난 묶음** — 이전 묶음에서 쓴 글감·본문과 비슷하면 막힌다.

```bash
node scripts/threads/insurance-set.mjs content/threads/insurance/sets/<날짜>.md
```

### 역할 5칸 — 읽는 사람의 마음이 어디서 열리는가

보험 이야기가 불편한 건 "팔려고 하는구나" 싶어서다. 그래서 다섯 칸 모두
**읽는 사람이 이득을 보는 쪽**에 서 있다. 가입을 권하는 칸은 없다.

| 역할 | 무엇을 쓰나 | 읽고 나서 드는 마음 | 예 |
|---|---|---|---|
| 오해풀기 | 흔히 믿는 것을 바로잡는다 | "아, 그런 거였어?" | 실손 두 개면 두 배로 받는다? |
| 숨은권리 | 받을 수 있는데 모르는 돈·권리 | "나도 찾아봐야겠다" | 보험금 청구는 3년 안에 |
| 증권한줄 | 증권에서 볼 칸 하나 | "내 거 한번 열어볼까" | 일상생활배상책임 특약 있는지 |
| 생활장면 | 지금 시기 일상과 보험을 잇는다 | "딱 지금 필요한 얘기네" | 연휴 운전 교대 전 운전자 범위 |
| 마음이야기 | 보험을 대하는 태도·공감 | "이 사람은 파는 사람이 아니구나" | 해지하기 전에 먼저 물어볼 것 |

마음이야기 칸이 신뢰를 만든다. 나머지 네 칸이 유익함을 만든다.
다섯 편 모두 정보를 주지만, 결론은 언제나 **"내 증권을 확인해 보자"** 쪽으로 착지한다.

### 보험 종류 (한 묶음 안에서 겹치지 않게)

실손 · 자동차 · 운전자 · 진단비(암·뇌·심장) · 배상책임(화재·일상) · 종신·정기 ·
연금·저축 · 어린이 · 치아 · 간병·치매 · 여행자 · 공통(청구·제도 전반)

## 한 편의 모양 (2026-10-02 사용자 양식)

**모바일 스레드에서 '더 보기'로 접히지 않는 길이**로 쓴다. 사용자가 실제로 쓰던 글이 기준이다
— 237자 / 14줄 / 한 줄 최대 23자 / 평균 16자.

```
1줄   제목 — 독자가 실제로 묻는 질문. 물음표로 끝내고, 뒤에 이모지 하나를 붙여도 된다
1줄   “따옴표 속 질문이나 말” — 사람들이 실제로 하는 말
1줄   공감·연결 ("정말 많이 물어보는 질문이에요")
5~8줄 사실 — 짧게 끊어서. 숫자·기간은 출처로 확인한 것만
1~2줄 과신을 덜어내는 말 ("상품마다 달라요")
1~2줄 해 볼 일 하나로 닫는다 ("○○부터 확인해 보세요 📋")
```

- **250자 이하, 16줄 이하, 한 줄 24자 이하.** 검사기가 막는다.
- 빈 줄 없이 줄바꿈만으로 이어 쓴다. 해시태그는 달지 않는다.
- **딱딱하지 않게** (2026-10-02 사용자 지시 — 처음 양식이 너무 딱딱했다). `~해요` / `~더라구요` 를 바탕으로 쓰고,
  `~입니다` 는 한 편에 한 번 이하로 줄인다. 마지막 줄은 단정보다 "봐 주세요", "확인해 보세요" 같은 권유로 닫는다.
- **말끝을 사람답게** (2026-10-02 사용자 지시 — 마침표만 이어지면 딱딱하다). 상황에 맞춰 느낌표(`!`, 놀랄 만한 사실은 `!!`),
  말줄임표(`…`, 망설임·여운), `~` 를 섞는다. 한 편에 2~3번쯤. 모든 줄에 붙이지 않는다. 검사기가 하나도 없으면 알려 준다.
- **"궁금한 건 친근한 설계사에게 물어보세요"** (2026-10-02 사용자 지시) — 증권 칸·조건이 상품마다 달라 혼자 보기 어려운 글에만,
  **한 묶음에 3편까지** 넣는다 (검사기가 센다). 문구는 이 모양 그대로 쓴다. "상담 신청", "DM", "문의 주세요" 같은 상담 유도는 계속 막는다.
  배너의 "친근한 설계사 강성대" 와 이어지는 문구다.
- **이모지는 문맥에 맞게 2~3개** (검사기가 센다). 제목 끝, 따옴표 속 말, 마지막 줄처럼 감정이 실리는 자리에 둔다.
  예: 🤔(헷갈리는 질문) 😥(곤란한 상황) 💡(알아 두면 좋은 사실) 📋🔍(증권 확인) ✅(체크) 💛(공감).
  돈 이모지(💰💵💸🤑)는 심의상 쓰지 않는다. 장식으로 줄마다 붙이지 않는다.
- 링크는 본문에 달지 않는다. 출처는 묶음 파일의 `출처:` 칸에 반드시 적는다.

예 (사용자 원문):

```
실손보험 있는데 다른 보험도 필요할까?
“실손 있는데 다른 보험까지 필요한가요?”
정말 많이 물어보는 질문이에요.
실손은 실제 사용한 의료비를
보장하는 역할이 중심이고,
진단비나 수술비는
정해진 조건에 해당하면
약속된 금액을 받는 방식이에요.
큰 질병이 생기면
병원비뿐 아니라 생활비, 간병비,
소득 감소까지 생길 수 있잖아요.
그래서 보험을 많이 가입하는 것보다
내 실손으로 부족한 부분이 무엇인지
확인하는 게 먼저입니다.
```

## 심의 — 보험 글에만 더 붙는 금지 (검사기가 막는다)

`memory/CLAUDE.md` [4] 를 스레드 길이에 맞게 옮긴 것이다.

- **일 단위 보험료 강조** — "하루 ○○원", "커피 한 잔 값" 쓰지 않는다
- **해지 권유** — "해지하세요", "갈아타세요" 쓰지 않는다 (BRAND NO LIST 3)
- **다른 회사·설계사 깎아내리기** — "○○생명보다", "설계사가 잘못 넣은" 쓰지 않는다 (2)
- **가입 권유** — "가입하세요", "들어 두세요", "지금 가입" 쓰지 않는다
- **돈 그림** — 💰💵💸🤑 같은 돈 이모지, ₩ $ 기호 쓰지 않는다
- **'보장'** 은 이름씨("보장 내용", "보장 범위")로만 쓴다. "보장합니다", "보장해 드립니다"
  처럼 약속하는 말은 안 된다 (안전장치가 막는다)
- 특약을 주계약처럼 쓰지 않는다 — "특약으로 들어 있는 경우가 많아요" 처럼 특약이라고 밝힌다
- 만기환급금·축하금 이야기를 하면 받는 조건을 같이 적는다
- DM·상담·문의 유도 금지는 voice.md 그대로다. 점검형 CTA 도 "성글벙글에게 상담받으세요"가 아니라
  "내 증권에서 확인해 보세요"까지만 쓴다 — 스레드 안전장치가 상담 유도를 막는다.

## 출처 (예외 없음)

- 숫자·기간·제도 이름이 나오면 `출처:` 에 **기관 · 자료명 · 링크**를 적는다. 링크가 없으면 검사기가 막는다.
- 정부·금융당국·보험협회·법령 원문만. 뉴스·블로그는 쓰지 않는다.
- `원문확인:` 칸에 링크를 직접 열어 봤는지 적는다 (`함` / `안 함`).
  클라우드 세션에서는 `law.go.kr`, `fsc.go.kr` 이 막혀 원문을 못 연다. 그럴 땐 `안 함` 으로 두고,
  **올리기 전에 사람이 링크를 열어 확인한다.** 검사기가 `안 함` 을 알려 준다.
- **예외·조건·"이런 경우는 안 돼요" 같은 예시도 사실이다** (2026-10-02 점검 — 7편 "건강진단 계약은 철회 불가"는
  예전 약관 기준이라 지금 법과 맞지 않았다). 예외 조건은 현행 법령·감독규정·금융당국 안내로 확인한 것만 쓰고,
  못 찾으면 예시 없이 "안 되는 경우도 있으니 보험사에 물어보세요"로 쓴다.
- **실손(실제 치료비)과 정액(진단비·수술비)을 섞어 말하지 않는다** (같은 점검 — 9편). 실손은 실제 낸 치료비 이상
  겹쳐 받을 수 없고, 정액 보장은 따로 나올 수 있다. "상품마다 달라요"로 뭉뚱그리지 않는다.

## 실제 광고심의(심의필)와의 관계

이 규칙과 검사기는 **심의에 걸릴 표현을 미리 걸러 내는 것**까지다.
소속 보험사·협회의 광고심의를 받아야 하는 글인지, 심의필 번호를 달아야 하는지는
소속 회사의 기준을 따른다. 받았으면 묶음 파일 `심의필:` 칸에 적어 둔다.

## Word 로 저장하기 (2026-10-02 사용자 요청)

한 편 = Word 파일 하나. 본문 밑에 **고정 사진**(심의 고지 배너, 모든 글에 같은 사진)만 붙인다.
사진 아래에는 아무것도 넣지 않는다 (2026-10-02 사용자 지시 — 작업 메모를 뺐다). 출처·원문 확인 여부는 묶음 파일에만 둔다.

```bash
python3 scripts/threads/insurance-word.py <묶음.md> <사진.jpg> <저장 폴더>
```

- **저장 위치: Google Drive `내 드라이브/ClaudeWorkspace/보험글/` 한 폴더에 `스레드 1편.docx`, `스레드 2편.docx` …**
  (2026-10-02 사용자 지시 — 날짜 폴더를 없앴다). 번호는 묶음 파일 이름 순서대로 이어서 매기므로, 새 묶음은 뒤에 붙고
  앞 번호는 바뀌지 않는다. **이미 올린 묶음 파일의 이름을 바꾸거나 중간에 끼워 넣지 않는다** — 번호가 밀린다.
  PC 에서 `launchers/insurance-word.cmd` 를 더블클릭하거나 `launchers/sync.cmd` 를 돌리면 저장된다.
  이미 있는 Word 는 원고·사진·실행기가 바뀌었을 때만 다시 만든다 (`-Force` 면 전부).
  클라우드 세션은 Drive 에 Word 를 직접 올리지 못한다(파일이 커서) — 저장은 PC 실행기가 한다.
- 고정 사진은 Google Drive `내 드라이브/ClaudeWorkspace/보험글-사진/` 에서 가장 최근 사진을 쓴다.
- 사진에 설계사 이름·등록번호가 있으므로 **사진과 Word 파일은 저장소에 커밋하지 않는다.**
- 배너의 심의필 번호는 아직 자리표시(`제26-00-0000호`)다. 실제 번호를 받은 사진으로 바꾸기 전에는 올리지 않는다.
