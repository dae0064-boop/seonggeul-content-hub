사용자가 **직접 가서 찍은 사진 5~10장**으로 올리는 글의 틀이다 (2026-10-26 사용자 요청). 원고는 Claude 가 전부 쓰고, 사용자는 사진·지도·발행만 한다.

## 왜 이 모양인가 — 근거

**① 우리 블로그 숫자** (Drive `blog-stats` 10/25 글별 조회수, `content/research/stats-log.md`)

- 「인천논현역 밥집 전주명가 순두부찌개 오징어볶음 점심 추천」(10/3) 이 하루 **13회로 블로그 전체 2위**였다.
  이 글보다 많이 읽힌 건 「되 돼 구분」 하나다. 3주가 지나도 꾸준히 읽혀 자동 원고 대부분보다 오래간다.
- 맛집 글로 들어온 검색어: `인천논현 밥집`, `인천 논현동 맛집 점심`, `논현동 순두부`, `논현동 짬뽕`, `시흥 카페고은`, `볼링장`.
  → **[지역·역] + [밥집/맛집/카페] + [상황(점심)]**, **[동네] + [메뉴 이름]**, **[지역] + [가게 이름]** 세 갈래로 들어온다.
- 유입 경로에 '플레이스'(1~11%)·'카카오맵'이 꾸준히 있다 → 글에 **네이버 지도(장소)를 꼭 붙인다.**

**② 다른 맛집 블로그·업계 글** (아래 출처)

- 검색하는 사람은 **매장 이름**으로 리뷰를 찾고, 예약 여부·주차·영업시간·대표 메뉴와 가격대를 본다.
- 점심 약속이면 빠른 식사·예약, 저녁 모임이면 단체석·주차가 더 중요하다 → **"누구와·언제 가면 좋은지"** 를 적는다.
- 모든 글을 똑같이 짜면 광고처럼 보인다 → 꼭 들어갈 칸만 정하고, 나머지는 그날 겪은 대로 쓴다.

**③ 우리 규칙** (`memory/CLAUDE.md`, `standards/이미지-기준.md`)

- 맛집 글은 **직접 찍은 사진만**. AI 그림을 실제 가게처럼 보이게 하지 않는다.
- 장점만 쓰지 않는다 → **아쉬운 점 한 가지**를 꼭 쓴다. 그게 후기를 믿게 만든다.
- 협찬·할인·무료 제공을 받았다면 **제목이나 글 맨 처음**에 눈에 띄게 밝힌다 (공정위 추천·보증 심사지침 — 2024-12 개정, 첫 부분 표시).
  내 돈으로 간 글은 본문에 따로 적지 않는다 (아래 '누가 무엇을 하나').

### Claude 가 원고를 쓸 때 지키는 것

- **사진이 1차 자료다.** 메뉴판·영수증·간판에서 읽은 메뉴 이름·가격·가게 이름을 쓴다. 사진 순서는 Claude 가 아래 "사진 배치" 대로 다시 정한다.
- **가게 정보(주소·영업시간·쉬는 날·주차)는 WebSearch 로 찾은 것 중 두 곳 이상이 같을 때만** 쓰고 "(방문일 기준, 바뀔 수 있어요)" 를 붙인다.
  못 찾은 칸은 기본 정보 상자에서 뺀다 — 지어내지 않는다. 지도는 사용자가 넣으므로 "자세한 위치는 아래 지도에서 확인해 주세요" 한 줄을 둔다.
- **맛·식감 느낌은 Claude 가 써 넣는다** (2026-10-26 사용자 — "구수했다, 쫄깃했다 같은 건 너가 직접 넣어줘"). 사진에 보이는 재료·조리법과 맞는 담백한 표현으로
  (들깨 국물 → 구수함, 숨만 죽인 미나리 → 아삭함). "인생 맛집"·"역대급" 같은 과장, 확인 안 된 사실(웨이팅 몇 분, 원산지, 손님 수)은 여전히 쓰지 않는다.
  사용자가 한마디 보내면 그것을 우선한다. 사용자 이름으로 나가는 글이라 실제 느낌과 다르면 사용자가 고친다.
- **아쉬운 점 한 가지**는 사진·확인된 정보에서 찾는다 (예: 자리가 좁아 보임, 주차 칸이 없음, 브레이크 타임). 정말 없으면 "점심엔 붐빌 수 있어요"처럼 단정하지 않는 팁으로 바꾼다.
- **본문에 '내돈내산' 글자를 쓰지 않는다** (2026-10-26 사용자 — "네이버가 안 좋아한다는 말이 있다"). 확인해 보니 그 글자 때문에 불이익을 준다는 공식 자료는 없고,
  네이버는 대신 **에디터 위 '내돈내산' 인증 버튼**(1년 안의 네이버 예약·주문·네이버페이 같은 방문·구매 이력 첨부)을 만들어 인증 글을 플레이스에 모아 보여 준다.
  → 인증 자료가 있을 때만 그 버튼을 쓰라고 안내하고, 본문에는 표기하지 않는다. **협찬·할인·무료 제공을 받은 글은 지금처럼 제목이나 첫 부분에 꼭 밝힌다**(공정위 지침 — 이건 빼면 안 된다).
- 제목·메인 키워드는 Claude 가 WebSearch 로 "[지역·역] 맛집/밥집" 류 검색어가 실제로 쓰이는지 보고 고른다 (아래 "제목").

## 제목

```
[지역·역] [밥집|맛집|카페] [가게 이름] [대표 메뉴 1~2개] [상황]
```

| 좋은 예 (우리 글) | 무엇이 들어갔나 |
|---|---|
| 인천논현역 밥집 전주명가 순두부찌개 오징어볶음 점심 추천 | 역 + 밥집 + 가게 + 메뉴 2 + 점심 |
| 시흥 카페 추천 카페고은, 두바이 쫀득쿠키와 소금빵 아메리카노 | 지역 + 카페 + 가게 + 메뉴 |
| 송도 미카도스시 가족 외식 후기, 아이와 먹기 좋은 회전초밥 | 지역 + 가게 + 상황 + 업종 |

- 맨 앞은 **지역·역 이름**. 사람들이 "○○역 맛집", "○○동 밥집"으로 친다.
- 가게 이름은 꼭 넣는다 — 가게 이름 검색이 맛집 글의 가장 큰 유입이다.
- 상황 말 하나: 점심 추천 · 가족 외식 · 아이와 · 혼밥 · 회식 · 데이트 · 주차 편한 · 24시간.
- 40자 안팎. "역대급", "인생 맛집", "무조건" 같은 과장은 쓰지 않는다.

## 분량·키워드·강조

자동 원고 기준(2,100~2,300자, 키워드 10회, 소제목 7~9)을 **적용하지 않는다.** 맛집 글은 사진이 중심이다.

- 본문 **공백 제외 1,400~1,800자** (2026-10-26 — 글자 수가 노출을 정한다는 공식 기준은 없다. 다만 네이버가 '충분한 분석·직접 경험'을 좋은 문서로 꼽아, 맛·식감·팁 문단으로 채운다). 사진 1장에 2~4줄.
- 메인 키워드(`[지역] [밥집|맛집|카페]`) **4~6회**, 가게 이름 **4~6회**, 대표 메뉴 이름 3회 안팎.
  억지로 넣지 않는다 — 맛집 글에 같은 말이 계속 나오면 바로 광고처럼 읽힌다.
- 줄 길이·덩어리는 평소와 같다 (한 줄 30자 안쪽, 2~4줄 덩어리).
- 색 강조는 줄인다: 빨간글씨 1~2 (한 줄 결론·아쉬운 점), 파란글씨 3~6 (가격·시간·거리), 노란배경 1~2 (방문 팁).
- 해시태그 10~15개 + 고정 3개(`서이추, 이웃추가, 서이추환영`).
  지역+맛집, 역+밥집, 가게 이름, 메뉴 이름, 지역+메뉴, 상황(점심·가족외식) 순서로.

## 하지 않는 것

- 먹지 않은 메뉴·가지 않은 날의 이야기를 쓰지 않는다.
- "인생 맛집", "역대급", "무조건 가세요" — 과장 금지.
- 다른 가게와 깎아내리며 비교하지 않는다.
- 협찬인데 내돈내산처럼 쓰지 않는다.
- 맛집 글에 보험 이야기를 넣지 않는다 (흐름이 끊기고 광고처럼 보인다).
- AI 그림을 넣지 않는다.
