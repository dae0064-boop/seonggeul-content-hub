# 블로그 이미지 기준

정해진 날: 2026-09-30. 기계가 읽는 정본은 `standards/image-style.json` 이다.
이 문서와 JSON 이 다르면 **JSON 을 고치고 이 문서를 맞춘다.**

## 스타일

**모든 그림은 클레이 3D 로 만든다.** 말랑한 무광 클레이, 파스텔 톤, 부드러운 조명,
단순한 배경. 글마다 스타일 문구를 바꾸지 않는다. 바꾸면 블로그 전체의 통일감이 깨진다.

|---|---|
| 모델 / 품질 | `gpt-image-2` / `low` (1장 약 8원) — **대표사진 포함 전부 low 만** (2026-10-08 사용자 지시). 계획서에 `quality` 를 적어도 `post-images.mjs` 가 무시한다 |

## 2026-10-27 네이버 원고부터 — 진한 색 + 대표사진마다 다른 사람·색·표정·글씨 (2026-10-26 사용자)

**생활보장도 클레이 3D 그대로** — 실사·클레이 시험 그림을 보고 사용자가 정함 ("클레이 3D 그대로 진행"). 생활보장 31번째 실사풍 전환은 취소(생활정보 151번째는 10/25 취소). `style_care`·`style_life` 는 남겨만 둔다.

왜 바꾸나: 블로그 첫 화면 대표사진 15장이 **모두 같은 캐릭터(민트 목도리 성글이)·같은 크림/살구 색·같은 주아체 글씨**라 서로 구분이 안 되고,
검색 결과에서도 위쪽 크림색 빈 벽·멀리 작은 두 사람·키워드만 반복한 글씨가 흰 화면에 묻혔다 (경쟁 1등은 얼굴 가까이·강조색·질문 글씨).
사용자: "상황별로 사람들, 색감, 표정, 글자 등 다양하게 변형해서 같은 느낌, 비슷한 느낌이 들지 않도록". 시험 그림 `close4-02-clay`(코랄 카디건·생각하는 얼굴·남색 띠 + "하루 얼마?")를 보고 "이 느낌으로".

|---|---|

| 대표사진 사람 | **고정 캐릭터(성글이·할머니·할아버지·자녀)를 쓰지 않는다.** 글 상황에 맞는 사람을 새로 — 나이·성별·옷·머리 모양. 계획서 1번 `thumb_person`(예: "60대 남성") |

| 표정 | `thumb_moods` 7개(생각·궁금·놀람·안심·반가움·결심·설명) 중 하나 — 계획서 1번 `thumb_mood`, 프롬프트에 그 문구. 겁먹은·슬픈·아픈 얼굴 금지 그대로 |
| 글씨 | overlay `look` = 아래 배치 하나 (10/28 까지 `"band"` 만), 두 줄 — 첫 줄 메인 키워드, 둘째 줄 질문 또는 짧은 답(10/29~)("하루 얼마?", "누가 받을까?"), 한 줄 10자 안쪽, 숫자 없음. `font: "jua"`(둥근) 또는 `"ptd"`(굵은 고딕) — 하루 두 가지 섞기 |
| 겹치지 않기 | 같은 날 네이버 글끼리 테마·사람·표정 모두 달라야 하고, 전날 같은 시각 글과 테마가 같으면 안 된다 (검사기) |

### 대표사진 배치·구도 섞기 (2026-10-29 네이버 원고부터, 2026-10-28 사용자)

사용자: "색감이랑 주제 제목만 다를 뿐 너무 비슷한 형식". 10/27~10/28 대표사진은 **모두** 위쪽 띠·한 사람 얼굴 가까이·
종이를 든 60~70대 여성(안경·턱 괴기)·둘째 줄 "~까?" 였다. 색과 글씨만 바꿔서는 다른 글로 보이지 않는다.
그래서 **글씨 배치와 그림 구도 자체를 글마다 바꾼다.** 정본 값은 `image-style.json` `thumb_layouts`·`thumb_shots`.

| 배치 `thumb_layout` (= overlay `look`) | 생김새 |
|---|---|
| `band` | 위쪽 색 띠에 흰 글씨, 첫 줄 강조색 (지금 방식) |
| `frame` | 색 테두리 + 위쪽 흰 글상자, 첫 줄 형광펜 |
| `bottom` | 사진은 위 70%, 아래 30% 는 색 띠 — 첫 줄 크게 강조색, 둘째 줄 흰 글씨 |
| `sticker` | 사진 꽉 채움, 왼쪽 아래 살짝 기운 흰 스티커(첫 줄) + 강조색 말풍선(둘째 줄) |
| `poster` | 색 바탕에 큰 글씨 두 줄, 사진은 오른쪽 아래 둥근 원 안 |

| 구도 `thumb_shot` | 장면 | 사람 |
|---|---|---|
| `face` | 한 사람 얼굴 가까이 | 있음 |
| `duo` | 나이 다른 두 사람이 마주 보고 이야기 (부모와 자녀 등) | 있음 |
| `hands` | 손만 크게, 핵심 동작 (얼굴 없음) | 손 |
| `object` | 핵심 사물 하나 크게 (사람 없음) | 없음 |
| `overhead` | 위에서 내려다본 탁자, 관련 물건 3~5개 | 없음 |
| `wide` | 방·장소 전체, 사람은 작게 (미니어처 느낌) | 있음 |

- 계획서 1번에 `thumb_layout`·`thumb_shot` 을 적고, 프롬프트 맨 앞에 그 구도의 `prompt` 문구와 배치의 `space` 문구를 넣는다 (`thumbnail_closeup` 은 10/28 원고까지).
- 사람이 없는 구도(`object`·`overhead`)는 `thumb_person: "없음"`, `thumb_mood` 를 적지 않는다.
- **같은 날 5편은 배치·구도 모두 다르게, 10편 날(~10/31)은 같은 것 2편까지.** 전날 같은 시각 글과 배치가 겹치지 않게.
- **둘째 줄은 질문(?)이 하루 절반까지** (5편 날 3편, 10편 날 5편). 나머지는 짧은 답·행동 — "이것만 보세요", "신청은 여기서", "한 달 기준 정리" (숫자 없음 그대로).
- **종이·안내문을 든 대표사진은 하루 1편**(10편 날 2편)까지 — 주제 사물(약봉투, 퍼즐, 체온계, 지팡이, 달력…)로 바꾼다.
- **60대 이상만 나오는 대표사진은 하루 2편**(10편 날 4편)까지 — 돌봄 글은 자녀·보호자 쪽 사람, 두 사람 구도, 사람 없는 구도로도 잡는다.
- 모두 검사기(`lint-post.mjs`)가 센다. 글씨는 로컬에서 얹으므로 배치를 바꿔도 비용은 그대로다.

본문 그림(2~8번)의 사람은 지금처럼 고정 캐릭터를 써도 되지만, 대표사진과 같은 사람·옷이 되지 않게 한다.

## 2026-10-01 바뀐 기준 (사용자 지시)

- **그림은 주제가 한눈에 보여야 한다.** 독감 글이면 예방접종 장면·반창고·의원(초록 십자)·체온계처럼.
  무섭거나 아파하는 표정만 피하고, 주사·의료 장면 자체는 금지하지 않는다.
- **대표사진에는 블로그 제목과 주제 글씨를 넣는다.** 본문 그림도 날짜·나이처럼 문맥상 필요하면 글씨를 넣는다.
- 글씨는 그림 모델이 그리지 않고, 계획서의 `overlay` 로 `scripts/lib/overlay.mjs` 가 얹는다 (대표사진은 Jua, 본문 띠·표는 맑은 고딕)
  (한글 깨짐·숫자 오류 방지). 그림 원본은 `NN.raw.png`, 글씨 얹은 결과가 `NN.png`.
  문구만 고칠 땐 `node scripts/post-images.mjs <계획서> --overlay-only` (돈 안 듦).

## 8장은 모두 다른 사진 (2026-10-01 사용자 지시)

- **한 글의 8장은 장소·주인공·구도·배경색이 서로 겹치지 않게** 잡는다. 보일러 글이면 보일러는
  대표사진 한 장에만 나오고, 나머지는 바깥벽 배기통·환기구 먼지 털기·경보기 버튼·집 평면처럼
  그 문단이 말하는 것을 보여 준다.
- **같은 그림에 글씨만 바꿔 얹지 않는다.** 글씨를 얹는 그림도 그 자체로 다른 장면이어야 한다.
- 각 장면은 `[이미지 N]` 바로 위 소제목 내용에 맞춘다 (2026-10-03 — 그림은 소제목 바로 아래에 둔다. 대표사진 1번만 예외).
- 프롬프트 끝에 "글 주제가 바로 보이게" 같은 공통 문장을 붙이지 않는다. 그 문장 때문에
  모든 그림에 같은 주제 사물(보일러)이 들어가 8장이 똑같아졌다. 대신 "설명한 것만 그린다"를 붙인다.

## 하지 않는 것 (2026-09-30 기준 — 위 바뀐 기준이 우선)

- **그림 안에 글자를 넣지 않는다.** 싼 품질에서 한글이 깨진다. 제목은 실행기가 따로 얹는다.
- 주사기·바늘·피·아파하는 모습을 넣지 않는다. 원고 규칙의 "공포로 행동 유도 금지"와 같은 선이다.

## 대표사진 제목

**2026-10-27 네이버 원고부터는 위 "진한 색 + 대표사진마다 다른…" 표가 앞선다** (띠 글씨·둘째 줄 질문·얼굴 가까이). 아래는 티스토리와 10/26 까지의 네이버.

그림 위쪽 3분의 1을 비워 두고, 실행기가 그 자리에 제목을 얹는다.

**2026-10-02 사용자 선택 — ① 둥근 글씨 + 형광펜** (맑은 고딕 글씨가 작고 밋밋했다).

- 글꼴은 **주아체(둥근 글씨)**, 진갈색에 두꺼운 흰 테두리. **첫 줄(메인 키워드)에 노란 형광펜**을 긋는다.
  글꼴 파일은 저장소에 함께 둔다 (`scripts/lib/fonts/`, SIL OFL). PC 에 깔지 않아도 똑같이 나온다.
- **크게.** 1024 그림에서 한 줄 150px 안팎 (예전 96px). 줄마다 칸에 맞춰 줄인다.
- **두 줄, 한 줄 10자 안쪽.** 첫 줄 = 메인 키워드, 둘째 줄 = 궁금증·방법.
  한 줄이 길면 글씨가 자동으로 줄어 작아진다 ("2026 독감 무료접종" 14자는 눈에 띄게 작았다).
  블로그 제목은 길어도 되지만 대표사진에는 줄인 문구를 쓴다.
- **위쪽 숫자·날짜·주제 꼬리표(`tag`)는 넣지 않는다.** 계획서에 적어도 그리지 않는다.
- 문구는 계획서 대표사진의 `overlay: { "kind": "thumb", "title": "줄1\n줄2" }` 에 적는다. 줄바꿈 자리는 직접 정한다.

- 제목은 `overlay.title` 두 줄(한 줄 10자 안쪽, 질문형 — 예 "냉장고 정리\n어디부터 할까?"). **메인 키워드만 노란 글씨**, 나머지 흰 글씨.
  메인 키워드·분류는 `post-images.mjs` 가 원고(.md)에서 읽는다. 로컬에서 합성한다 (비용 0).
- 사진 칸은 그림 아래쪽(주인공 자리)을 보여 준다. 1번 그림 프롬프트는 지금처럼 "위쪽 3분의 1 비우기"를 둬도 된다.

## 정보 카드 (2026-10-12 원고부터, 2026-10-02 사용자 결정)

글 1편 8장 중 **2~3장**(네이버는 2026-10-19 원고부터 **1~2장** — 한 주 시험)은 단계·확인 목록·비교를 글자로 정리한 카드로 바꾼다. **OpenAI 를 부르지 않고** `post-images.mjs` 가 로컬에서 그린다 (비용 0).
나머지는 지금 점토 3D 그림. 1번(대표사진)은 카드로 만들지 않는다.

```json
{ "n": 4, "file": "04.png", "title": "냉장고 정리 순서를 다섯 단계로 정리한 카드", "kind": "card",
  "card": { "type": "steps", "title": "냉장고 정리 순서", "items": ["안쪽부터 전부 꺼내기", "칸마다 주인 정하기", "..."] } }
```

| type | 모양 | items |
|---|---|---|
| `steps` | ①②③ 단계 | 3~5줄, 한 줄 16자 안쪽 |
| `check` | ✔ 확인 목록 | 3~5줄, 한 줄 16자 안쪽 |
| `compare` | ⭕ / ❌ 두 칸 (`heads` 로 칸 제목) | `[["왼쪽", "오른쪽"], ...]` 2~4줄, 칸 12자 안쪽 |

- **카드 글자는 원고 본문에 있는 말 그대로** (검사기가 본문에서 찾는다). 카드 title 은 16자 안쪽.
- **돈·통화기호·금액은 쓰지 않는다** (₩·$·"3만 원"·지폐·동전 — 검사기·`post-images` 가 막는다).
- 카드 자리도 그 소제목 바로 아래다. `prompt`·`shot`·`bg` 는 적지 않아도 된다. 원고 `[이미지 N]` 설명 = 계획서 `title` (대체텍스트).

## 계획서와 실행

- 계획서: `content/image-plans/<원고 슬러그>.json` — Claude 가 원고와 함께 쓴다
- 실행: 노트북·사무실 PC 에서 `ClaudeWorkspace\post-images.cmd` 더블클릭 (준비 중)
- 결과: `내 사진\성글벙글 이미지\<슬러그>\`

클라우드 세션은 `api.openai.com` 이 막혀 있어 이미지를 직접 만들 수 없다.
