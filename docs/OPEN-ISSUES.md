# 미해결 과제

판단이 필요해 손대지 않은 것들. 고칠 때 이 문서도 함께 지운다.

## 1. 출처·기준일 블록을 게이트로 올릴지

`write-post` 스킬은 "닫는 인사 바로 앞에 출처와 기준일을 적는다"고 무조건으로 적혀 있다.
그런데 기준이 된 발행글(`2026-09-12-aircon-cover.md`)에는 이 블록이 없다.
답하는 공식 기관이 없는 순수 생활 노하우라 인용할 1차 자료가 없었기 때문이다.

지금은 검사기가 **경고만** 한다(`· 마지막 닫는 인사 앞 출처·기준일이 없습니다`).
규칙과 실제가 어긋난 상태다.

**정할 것**: 둘 중 하나.
- 수치·제도를 인용한 글에만 요구한다 → 스킬 문구를 "인용한 자료가 있으면"으로 고친다.
  검사기는 숫자·기관명이 본문에 있을 때만 요구하도록 조건을 붙인다.
- 글 종류를 가리지 않고 요구한다 → 경고를 오류로 올리고, 자료가 없는 글에는
  "직접 해보고 정리했습니다" 같은 대체 문구 규격을 정한다.

## 2. `scripts/check_post.py` 가 현재 원고 형식으로는 돌지 않는다

한글 앞머리(`제목:` `타겟:` `목적:`)를 전제로 쓰였는데 실제 원고는 영문 키
(`title:` `main_keyword:`)를 쓴다. 분량 세는 법도 `lint-post.mjs` 와 달라
같은 원고를 2,310자 / 2,854자로 다르게 센다.

이 파일이 갖고 있던 검사 중 **광고 심의 금지어와 이미지 장수는 `lint-post.mjs` 로
옮겼다.** 남은 것은 두 가지다.

- **출처 URL 유무** — 1번을 정한 뒤에 붙인다.
- **Q&A 개수(3~5개)** — 현재 원고의 Q&A는 `Q.` 같은 표시 없이 산문으로 쓴다.
  기계적으로 셀 방법이 없어 옮기지 못했다. Q&A 구간을 표시로 감쌀지 정해야 한다.

**할 일**: 위 둘을 옮기고 나면 `check_post.py` 를 지운다.
그 전까지 발행 판단은 `lint-post.mjs` 로만 한다.

## 3. `유형: 구조설명` 앞머리 필드가 사라졌다

`check_post.py` 는 이 값이 `구조설명` 이면 출처 URL 요구를 건너뛴다.
그런데 실제 원고 앞머리에는 이 필드가 없어서 항상 출처를 요구한다.
1번·2번을 고칠 때 같이 정한다 — 이 구분을 유지할지, 없앨지.
