## 원고 — 네이버와 같은 지침 (2026-10-02 사용자 지시)

**서식·말투·인사말은 네이버 원고와 같다.** `CLAUDE.md` 의 글쓰기 규칙을 그대로 따른다 —
의미 단위 줄바꿈(한 줄 30자 이하), 2~4줄 덩어리, `[빨간글씨]`·`[파란글씨]`·`[노란배경]` 강조(3~5·6~10·3~5곳),
`인용구(소제목)`, `~해요` 체, 고정 여는 인사, 공백 제외 2,100~2,300자, 메인 키워드 10회·서브 각 5회,
제목은 메인 키워드로 시작 + 서브 1~2개, Q&A 3쌍, 이미지 8자리, 주제 태그 15개.

네이버와 **다른 것은 셋뿐**이다.

| 항목 | 네이버 | 티스토리 |
|---|---|---|
| 닫는 인사 첫 줄 | 좋아요·공감과 이웃추가 부탁드려요💙 | 좋아요·공감과 **구독** 부탁드려요💙 (티스토리엔 이웃이 없다) |
| 고정 태그 | 서이추·이웃추가·서이추환영 | 붙이지 않는다 |
| 내용·제목·메인 키워드 | — | 네이버 글과 **달라야 한다** (같은 묶음, 다른 키워드) |

`content/tistory/<날짜>-<슬러그>.md` 가 정본이다. 앞머리는 네이버 원고와 같고 `source_post`(같은 묶음의 네이버 글)를 더 적는다.
`.json`(스크립트 입력)·`.html`(붙여넣기용)은 생성물이니 고치지 않는다. 이미지 계획서는 `content/image-plans/<슬러그>.json` 으로 네이버와 같다.

```bash
node scripts/lint-tistory.mjs content/tistory/<원고>.md     # 통과해야 올린다
node scripts/build-tistory.mjs content/tistory/<원고>.md    # .json · .html 생성
```

`lint-tistory.mjs` 는 두 단계다.

1. 서식: 네이버 검사기를 `lint-post.mjs --tistory` 로 그대로 돌린다 (위 표의 두 가지만 다르게 본다).
2. 네이버와 겹침: `content/posts/` 의 네이버 글 **전부**와 견준다 (고정 인사말은 빼고 센다).

| 항목 | 불통과 기준 |
|---|---|
| 메인 키워드 | 네이버 글의 메인 키워드와 같거나, 제목에 네이버 메인 키워드가 그대로 들어감 |
| 제목 | 네이버 제목과 유사도(글자 2개 조각) 40% 이상 (25% 이상이면 알림) |
| 본문 | 네이버 글과 10글자 조각 겹침 15% 이상 (8% 이상이면 알림) |

### HTML 로 바꿀 때

`build-tistory.mjs` 가 원고를 티스토리 에디터용 HTML 로 바꾼다 (`scripts/lib/parse-tistory.mjs`).

- 덩어리 = `<p>` 하나, 원고의 줄바꿈 = `<br>`. 덩어리 사이에 빈 문단 한 줄. 인용구·이미지 위아래는 빈 줄 없이 붙인다
- 인용구(소제목) = `<h2>` 를 인용구 모양(위 따옴표 + 아래 밑줄)으로. 독자 눈엔 인용구, 구글에는 소제목으로 잡힌다
- 빨강 `#ff0010`·파랑 `#0078cb` 글자색, 노란 배경 `#fff8b2`, 셋 다 굵게
- 스킨에 따라 인용구 모양이 조금 다르게 보일 수 있다

"티스토리는 강제 줄바꿈을 하면 구글 평가가 나빠진다"는 예전 기준(`standards/발행-운영기준.md`)은 근거를 찾지 못해 따르지 않는다.

## 발행 스크립트

```bash
node scripts/publish-tistory.mjs --post content/tistory/<원고>.json --save-draft --dump
```

- 블로그는 `--blog <이름>` 또는 환경변수 `TISTORY_BLOG`.
- 본문은 한 줄씩 치지 않고 HTML 을 기본 에디터(TinyMCE)에 통째로 넣는다. **HTML 모드 화면은 쓰지 않는다** —
  거기 넣은 글은 저장되지 않았다(2026-10-03 실제 테스트: 사진만 저장됨). 모드 전환 확인창은 언제나 거절한다.
  넣은 뒤 **소제목(H2) 개수·색 강조 개수·글자 수를 다시 읽어 맞춰 보고, 다르면 저장하지 않는다.**
  (에디터가 색을 지우면 강조가 조용히 사라지므로 색 개수까지 본다)
- 저장 버튼 글자에 `발행·완료·공개` 가 보이면 멈춘다.
- `--publish-now` 는 '공개'가 선택된 것을 확인한 뒤에만 누른다. 사람이 그 자리에서 붙일 때만 쓴다.
- attach 한 크롬은 끄지 않는다. 탭도 닫지 않는다.
- 사진 `--images content/images/<슬러그>`: 빈 본문에 `NN.png` 를 1번부터 한 장씩 올리고(첨부 → 사진),
  그림 수가 늘었는지로 확인한다. 다 올리면 기본 에디터에 생긴 그림 덩어리를 순서대로 읽어 원고의 `[이미지 N]` 자리에 끼우고
  본문 전체를 덮어쓴다. 수가 다르면 사진 없이 글만 넣고, 한 장이 실패하면 뒤 장은 올리지 않으며 못 넣은 자리 번호를 알려 준다.
- 저장 직전에 기본 에디터 내용(저장될 내용)을 다시 읽어 소제목·색 강조·그림·글자 수가 맞지 않으면 저장하지 않는다.
- 자동화가 막히면 `content/tistory/<원고>.html` 을 에디터 HTML 모드에 붙여넣으면 된다.
