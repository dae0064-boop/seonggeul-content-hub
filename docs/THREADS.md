# 스레드 자동화

내가 쓰지 않아도 스레드에 글이 올라가고, 달린 댓글에 답이 달린다.
GitHub Actions 가 정해진 시간에 깨어나 돌리므로 **내 컴퓨터가 꺼져 있어도 돈다.**

애매한 것은 절대 자동으로 답하지 않는다. 답하지 않고 이슈로 넘긴다.

## 무엇이 언제 도는가

| 워크플로 | 언제 | 하는 일 |
|---|---|---|
| `스레드 발행` | 매일 08:10 · 12:40 · 19:10 · 22:10 (KST) | 글 한 편을 만들어 올린다 |
| `스레드 댓글` | 매시 25분 | 새 댓글에 답한다. 애매하면 이슈로 넘긴다 |
| `스레드 토큰 갱신` | 매달 1일 · 15일 | 60일짜리 토큰을 미리 갱신한다 |
| `스레드 점검` | 직접 실행할 때만 | 아무것도 올리지 않고 연결만 확인한다 |

시각을 바꾸려면 `.github/workflows/threads-*.yml` 의 `cron` 을 고친다. **cron 은 UTC 다**
(한국시간 = UTC + 9). GitHub 의 예약 실행은 몇 분에서 십몇 분까지 늦을 수 있다.

## 설치 — 한 번만 하면 된다

### 1. 스레드 앱 만들고 토큰 받기

[Meta 개발자 콘솔](https://developers.facebook.com/apps) 에서:

1. 앱 만들기 → 용도에서 **Threads API** 를 고른다
2. 권한(스코프)에 네 가지를 넣는다
   - `threads_basic` — 내 계정과 글 읽기
   - `threads_content_publish` — 글 올리기
   - `threads_read_replies` — 댓글 읽기
   - `threads_manage_replies` — 답글 달기
3. 내 스레드 계정을 연결하고 **장기(long-lived) 액세스 토큰**을 받는다

받은 토큰은 60일짜리다. 아래 토큰 갱신 워크플로가 만료 전에 알아서 늘려준다.

### 2. Anthropic API 키 받기

[console.anthropic.com](https://console.anthropic.com) → API Keys 에서 발급.
글을 쓰고 댓글을 판단하는 데 쓴다.

### 3. GitHub 저장소에 넣기

**Settings → Secrets and variables → Actions → Secrets** (값이 감춰진다)

| 이름 | 값 |
|---|---|
| `THREADS_ACCESS_TOKEN` | 1번에서 받은 장기 토큰 |
| `ANTHROPIC_API_KEY` | 2번에서 받은 키 |
| `THREADS_SECRET_PAT` | (선택) 토큰 자동 갱신용. 아래 설명 |

`THREADS_SECRET_PAT` 는 토큰을 자동으로 덮어쓰기 위한 것이다. 없어도 돌지만,
60일마다 토큰을 손으로 바꿔야 한다. 넣으려면
[파인그레인드 토큰](https://github.com/settings/personal-access-tokens) 을 이 저장소에만
`Secrets: Read and write` + `Metadata: Read-only` 로 발급해 넣는다.

**Settings → Secrets and variables → Actions → Variables** (값이 보인다. 없으면 기본값)

| 이름 | 기본값 | 뜻 |
|---|---|---|
| `THREADS_PAUSED` | (없음) | `true` 면 전부 멈춘다 |
| `THREADS_MAX_POSTS_PER_DAY` | 4 | 하루 최대 발행 수 |
| `THREADS_MAX_REPLIES_PER_RUN` | 10 | 한 번 실행에 다는 최대 답글 수 |
| `THREADS_REPLY_MAX_AGE_HOURS` | 72 | 이보다 오래된 댓글은 답하지 않는다 |
| `THREADS_MODEL` | `claude-sonnet-5` | 글을 쓰는 모델 |

### 4. 점검하고 시험 발행

1. Actions 탭 → **스레드 점검** → Run workflow. 전부 `[정상]` 이어야 한다
2. **스레드 발행** → Run workflow → `dry_run` 을 **켠 채로** 실행.
   올리지 않고 어떤 글이 만들어지는지만 보여준다. 로그에서 글을 읽어본다
3. 마음에 들면 `dry_run` 을 끄고 한 번 실행해 실제로 올라가는지 본다
4. 그 다음부터는 예약대로 알아서 돈다

## 멈추는 법

급할 때는 아무거나 하나면 된다. 셋 다 즉시 먹는다.

1. **Variables 에 `THREADS_PAUSED` = `true`** — 가장 빠르다. 저장소 설정에서 한 줄
2. **`content/threads/PAUSE` 파일을 만들어 커밋** — 파일 안에 이유를 적어두면 로그에 같이 찍힌다
3. **Actions 탭에서 워크플로 Disable**

다시 돌릴 때는 되돌리면 된다.

## 무엇이 자동으로 막히는가

`scripts/threads/guard.mjs` 가 나가기 직전에 검사한다. 하나라도 걸리면 **올리지 않고**
이슈를 연다. 조용히 넘어가지 않는다.

- 500자 초과, 80자 미만
- `무조건`(부정 없이) · `100%` · `공짜` · `단언컨대` · `절대로` · `손실 없음`
- `최고의` · `가장 좋은` 같은 우위 단정
- 완치·치료·원금보장·수익보장 같은 진단/수익 단정
- DM·상담·구매 유도 같은 영업 문구
- `큰일 납니다` 같은 공포 자극
- 전화번호 · 이메일 · 계좌 · 주민번호 형태
- 링크 2개 이상, 단축 URL, 블로그·나무위키 같은 2차 가공 출처
- 해시태그 6개 이상
- 블로그 전용 양식(`[빨간글씨]`, 고정 인사말)이 섞인 경우
- **최근 글과 너무 비슷한 글** (문자 3-gram 유사도 0.42 이상)

글을 만들 때는 걸린 이유를 모델에게 돌려주고 최대 3번까지 다시 쓴다.
3번 다 걸리면 그 회차는 올리지 않는다.

## 댓글은 어디까지 자동인가

**자동으로 답한다**: 인사, 공감, 감사, 글 내용에 대한 가벼운 질문, 경험 공유.

**답하지 않고 이슈로 넘긴다**:

- 욕설·공격
- 정치·종교
- 의료 판단 요청 (무슨 병인지, 약을 먹어도 되는지)
- 금융·법률 판단 요청 (수익률, 소송, 합의금)
- 광고·협찬·맞팔·DM 요청
- 개인정보가 담긴 댓글
- 사실관계 항의·정정 요구
- 링크가 달린 댓글
- 모델이 조금이라도 애매하다고 본 것

앞의 여덟 가지는 모델에게 묻기 전에 정규식으로 먼저 걸러낸다. 모델 판단을 기다리지 않는다.

보류된 댓글은 `threads-hold` 라벨이 붙은 이슈로 올라온다. 이슈에 원글·댓글·보류 사유와
(만들어졌다면) 답글 초안이 같이 담긴다. 사람이 직접 답하고 이슈를 닫으면 된다.
**같은 댓글로 이슈가 두 번 열리지는 않는다.**

## 같은 댓글에 두 번 답하지 않는 이유

상태 파일을 쓰지 않는다. GitHub Actions 는 매번 새 러너라 파일이 남지 않기 때문이다.

대신 **스레드 API 를 되읽어 판단한다.** 내 글의 대화를 전부 가져와, 내 계정이 그 댓글에
단 답글이 이미 있으면 답한 것으로 본다. 로그가 날아가도, 실행이 중간에 죽어도,
두 번 답하지 않는다. 하루 발행 수도 같은 방식으로 스레드에서 세어 온다.

## 내 PC 에서 돌려보기

```bash
npm run threads:selftest      # 진짜 계정에 붙지 않고 배관만 확인 (키 없어도 된다)
npm run threads:doctor        # 연결 점검
npm run threads:compose       # 글 초안만 만들어 본다 (올리지 않는다)
npm run threads:publish:dry   # 발행 직전까지 가고 멈춘다
npm run threads:replies:dry   # 무엇을 답할지만 보여준다
```

키는 저장소 루트의 `.env` 에 넣는다 (`.env.example` 참고). `.env` 는 커밋되지 않는다.

직접 쓴 글을 올리려면:

```bash
node scripts/threads/publish.mjs --from 초안.txt
```

`--from` 으로 넣은 글도 안전장치를 똑같이 거친다.

스크립트를 고쳤으면 `npm run threads:selftest` 를 먼저 돌린다. 스레드 API 와 Anthropic API 를
흉내 내는 서버를 잠깐 띄워 발행·댓글 경로를 그대로 태워보는 것이라, 키도 네트워크도 필요 없다.

> **클라우드 세션에서는 돌지 않는다.** Anthropic 컨테이너에서 도는 Claude 세션은
> `graph.threads.net` 이 egress 정책에 막혀 있다(네이버와 같은 상황). 스크립트를 고치고
> 커밋할 수는 있지만 실제 발행·댓글 조회는 GitHub Actions 나 내 PC 에서만 된다.

## 글의 말투를 바꾸고 싶을 때

`content/threads/voice.md` 를 고친다. 코드가 아니라 이 파일이 정본이고,
자동화가 매번 이 파일을 그대로 읽어 모델에게 넘긴다.

글감은 `content/threads/topics.txt` 에 한 줄에 하나씩 적는다.
최근에 올린 글과 겹치는 글감은 알아서 피한다. 비어 있으면 그 달의 계절 흐름에 맞춰 직접 잡는다.

## 비용

- **GitHub Actions**: 공개 저장소는 무료. 비공개면 실행 시간이 과금된다.
  지금 설정(발행 4회 + 댓글 24회)으로 월 700~900분쯤 쓴다. 무료 한도 2,000분 안이지만
  다른 워크플로가 있으면 댓글 cron 을 `25 */2 * * *` (두 시간마다) 로 늘린다.
- **Anthropic API**: 글 한 편과 댓글 하나가 각각 짧다. 하루 몇 센트 수준이다.
- **스레드 API**: 무료. 24시간에 글 250개, 답글 1,000개까지.

## 토큰 다시 받기

토큰이 만료돼 자동 갱신이 실패하면 이슈가 열린다. 그때는:

1. [Meta 개발자 콘솔](https://developers.facebook.com/apps) 에서 장기 토큰을 새로 받는다
2. 저장소 Settings → Secrets → `THREADS_ACCESS_TOKEN` 을 새 값으로 바꾼다
3. Actions 탭에서 **스레드 점검** 을 돌려 `[정상]` 인지 확인한다

## 잘 안 될 때

| 증상 | 확인할 것 |
|---|---|
| 아무것도 안 올라온다 | `THREADS_PAUSED` 가 켜져 있는지, `content/threads/PAUSE` 가 있는지, Actions 가 Disable 됐는지 |
| `스레드 API 401` / `190` | 토큰 만료. 위 "토큰 다시 받기" |
| `스레드 API 400` + 권한 얘기 | 스코프 4개가 다 들어갔는지. 하나라도 빠지면 그 동작만 막힌다 |
| 글은 올라가는데 댓글 답이 없다 | `스레드 댓글` 워크플로 로그. 보류로 넘어갔으면 `threads-hold` 이슈를 본다 |
| 같은 얘기를 자꾸 올린다 | `content/threads/topics.txt` 를 채운다. 중복 판정을 더 빡빡하게 하려면 `THREADS_DUP_THRESHOLD` 를 낮춘다 |
| 안전장치에 너무 자주 걸린다 | 이슈에 걸린 항목이 적힌다. 규칙이 과하면 `scripts/threads/guard.mjs` 를 고친다 |

엔드포인트 규격이 바뀌어 전부 400 이 나면 `scripts/threads/api.mjs` 위쪽의
`EP` / `FIELDS` 만 고치면 된다. 주소와 필드 이름을 전부 거기 모아뒀다.
