# 새 컴퓨터에서 시작하기

집·회사·노트북 각각에서 한 번씩만 하면 된다. 이후로는 자동이다.

## 1. 구글 드라이브 데스크톱 확인

`내 드라이브` 아래에 `성글벙글 원소스 멀티콘텐츠 자동화 구현` 폴더가 보이는지
확인한다. 보이지 않으면 드라이브 앱에서 해당 폴더를 오프라인 사용으로 설정한다.

폴더 위치는 운영체제마다 다르다.

| 환경 | 경로 |
|---|---|
| Windows | `G:\내 드라이브\성글벙글 원소스 멀티콘텐츠 자동화 구현` |
| macOS | `~/Library/CloudStorage/GoogleDrive-<계정>/내 드라이브/성글벙글 원소스 멀티콘텐츠 자동화 구현` |

## 2. 저장소 받기

```bash
git clone <저장소 주소> seonggeul-content-hub
cd seonggeul-content-hub
```

저장소 자체는 드라이브 폴더 **밖에** 두는 것을 권한다. 드라이브가 `.git`
디렉터리를 실시간 동기화하면 파일이 깨질 수 있다. 결과물만 드라이브로 복사된다.

## 3. 연결 확인

```bash
./scripts/drive-sync.sh status
```

`드라이브 폴더: ...` 로 시작하는 출력이 나오면 끝이다.

폴더를 찾지 못한다는 메시지가 나오면 경로를 직접 알려준다. 저장소 루트에
`.drive-local` 파일을 만들고 (이 파일은 git에 올라가지 않는다):

```bash
HUB_DRIVE_DIR="/실제/경로/내 드라이브/성글벙글 원소스 멀티콘텐츠 자동화 구현"
```

## 4. 이후

Claude Code로 이 저장소를 열면

- 세션이 시작될 때 드라이브에서 최신 상태를 가져오고,
- 세션이 끝날 때 드라이브로 내보낸다.

훅이 도는지 보려면 `.drive-sync.log`를 확인한다.

## 컴퓨터를 옮길 때

떠나는 컴퓨터에서 커밋하고 푸시한다. 도착한 컴퓨터에서 `git pull` 한다.
드라이브 동기화는 자동으로 되지만, git이 정본이라 커밋해 두는 편이 안전하다.

## 문제가 생기면

| 증상 | 확인할 것 |
|---|---|
| 드라이브에 파일이 안 올라간다 | `.drive-sync.log`, `./scripts/drive-sync.sh status` |
| 지운 파일이 되살아난다 | 삭제는 전파되지 않는다. 양쪽에서 지우거나 `_archive/`로 옮긴다 |
| 훅이 안 돈다 | Claude Code에서 `/hooks`를 한 번 열어 설정을 다시 읽힌다 |
| 같은 파일을 두 컴퓨터에서 동시 수정했다 | 나중에 저장된 쪽이 남는다. git 이력에서 이전 버전을 꺼낸다 |
